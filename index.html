agent-network-digitalocean

Desired state for one minimal NetBird Agent Network demo: Traefik, the combined netbird-server, the dashboard in agent-network view, the private reverse proxy — and an isolated agent with no key and no internet route — on a single guarded DigitalOcean Droplet in Amsterdam.

Same package, second provider: this is the agent-network Package Skill that also runs agent-network-vultr, selected onto DigitalOcean by provider-compute: digitalocean and the digitalocean-* keys alone, under the workspace Compute Provider Standard. The isolation is still the demo: the agent container holds no API key and has no internet route, and its requests reach Anthropic only through the overlay and the policy-gated proxy.

Endpoints

agent-network-digitalocean.bigconfig.online serves the dashboard, the REST API, management and signal gRPC, the relay and the embedded IdP; one generated label beneath it is the keyless agent-network endpoint, tunnel-only. The firewall admits 22 from the SSH sources, 80 and 443 from the HTTP sources, and STUN on UDP 3478 from the STUN sources; nothing else.

Use

direnv allow
./green build
./green create --dry-run
./green create

Build and dry-run are credential-free and never read ~/.ssh. Real creation converges the droplet in the region's default VPC, its cloud firewall, the two Cloudflare records and the gateway stack, bootstraps the control plane headlessly, builds the agent, and proves every claim. Deletion stays guarded by compute-prevent-destroy: true; a change of provider-compute on a profile with a machine in state is refused.

The machine keypair is not in this repository

Keygen mode: colors.yml carries no digitalocean-ssh-keys, so the package generates and owns ~/.ssh/agent-network-digitalocean outside the checkout. Cloning this repository elsewhere does not carry machine access.

Provenance

colors.yml (the only editable desired state), the three installed agent-network Package Skill payloads and their lockfile, root launchers copied from those payloads, toolchain files, documentation, and verification.md. Credentials live in gitignored .envrc.private; generated output in .colors/ is never committed.
